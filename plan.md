# Musify Lite Build Plan

## 1. Project summary

**Musify Lite** will be a static, single-page music interface hosted on GitHub Pages. It will be designed specifically for a restricted network where GitHub Pages and the selected Invidious instance work, but YouTube, GoogleVideo, custom homelab services, and direct Invidious API access are blocked.

Musify Lite will not attempt to bypass browser security controls. Instead, it will use the parts already confirmed to work:

- GitHub Pages for the application interface.
- The Invidious website for native search and browsing.
- The Invidious embed player for playback.
- `listen=1` for the compact audio-oriented player.
- The Invidious companion proxy for media delivery.
- Browser storage for favorites, playlists, history, settings, and the queue.

The core design rule is:

> Musify Lite manages the user's library and listening workflow, while Invidious handles search navigation and playback inside isolated iframes.

---

## 2. Confirmed environment

### Confirmed working

- GitHub Pages loads on the target network.
- `https://invidious.tiekoetter.com/search?q=...` opens and returns search results.
- `https://invidious.tiekoetter.com/embed/VIDEO_ID` loads inside an iframe hosted on GitHub Pages.
- `https://invidious.tiekoetter.com/embed/VIDEO_ID?listen=1` loads as an audio-oriented player.
- Media is relayed through `eu-de1.companion.invidious.tiekoetter.com`.
- The companion-hosted media plays even though direct `googlevideo.com` access is blocked.

### Confirmed unavailable

- Direct Invidious API requests return `403` or are unavailable.
- JavaScript on GitHub Pages cannot read Invidious pages because Invidious does not return an `Access-Control-Allow-Origin` header.
- The parent application cannot read, restyle, or inspect the cross-origin iframe.
- The parent application cannot reliably detect which search result was clicked inside the iframe.
- The parent application cannot assume it can directly control play, pause, volume, seeking, or track-ended events inside the iframe.

### Architectural consequence

Version 1 must not depend on:

- Invidious JSON APIs.
- Fetching or parsing Invidious HTML.
- Reading iframe contents.
- A custom backend.
- A home server.
- Cloud functions.
- Direct YouTube or GoogleVideo connections.
- Automatic metadata extraction.

## 3. Definition of a successful first release

Version 1 is successful when a user can:

1. Open Musify Lite from GitHub Pages.
2. Search through the native Invidious search page embedded in the app.
3. Paste a YouTube or Invidious URL, or enter a video ID.
4. Load that item in an Invidious `listen=1` embed.
5. Save it as a favorite.
6. Add it to a manual queue or playlist.
7. Move between queue entries using Previous and Next.
8. Restore the library and queue after reopening the page.
9. Export and import all local application data.
10. Use the application on desktop and mobile without a backend.

## 6. Application architecture

### 6.1 UI layer

The UI layer renders:

- Header and global search field.
- Sidebar on desktop.
- Bottom navigation on mobile.
- Home dashboard.
- Search view.
- Now Playing view.
- Queue drawer.
- Favorites view.
- Playlist manager.
- History view.
- Settings view.
- Dialogs, notices, and validation messages.

### 6.2 State layer

One in-memory application state object should be the source of truth during a session.

```javascript
const state = {
  settings: {},
  currentTrack: null,
  queue: [],
  queueIndex: -1,
  favorites: [],
  playlists: [],
  history: [],
  searchHistory: [],
  currentView: "home"
};
```

Every state-changing action should:

1. Validate the requested change.
2. Update `state`.
3. Save the relevant section to browser storage.
4. Re-render only the affected interface.

### 6.3 Storage layer

Use `localStorage` for the MVP because the stored data is small and structured. Keep all storage access behind helper functions so IndexedDB can replace it later if needed.

Suggested keys:

```text
tunoMusic.version
tunoMusic.settings
tunoMusic.queue
tunoMusic.favorites
tunoMusic.playlists
tunoMusic.history
tunoMusic.searchHistory
```

Suggested wrapper functions:

```javascript
loadJSON(key, fallback)
saveJSON(key, value)
removeStoredKey(key)
exportLibrary()
importLibrary(data)
resetApplicationData()
```

### 6.4 Invidious URL layer

All Invidious URLs must be generated through centralized functions.

```javascript
createSearchUrl(query)
createEmbedUrl(videoId, options)
createWatchUrl(videoId, options)
createInstanceHomeUrl()
```

Do not repeat the domain string throughout the application.

Default configuration:

```javascript
const DEFAULT_SETTINGS = {
  instance: "https://invidious.tiekoetter.com",
  defaultPlayerMode: "listen",
  autoplay: true,
  localProxy: true,
  rememberQueue: true,
  theme: "dark",
  historyLimit: 100
};
```

## 7. Data models

### 7.1 Track

```javascript
{
  id: "fonVCRfecQE",
  title: "User-entered title or video ID",
  artist: "Optional artist",
  thumbnail: "",
  sourceUrl: "Optional original pasted URL",
  addedAt: 1792800000000,
  lastPlayedAt: 1792800000000,
  playCount: 1
}
```

Rules:

- `id` is required.
- `title` falls back to the video ID.
- `artist` is optional.
- Remote metadata is not required.
- Duplicate IDs should be detected before adding to favorites or a playlist.

### 7.2 Playlist

```javascript
{
  id: "playlist-generated-id",
  name: "My Playlist",
  description: "",
  createdAt: 1792800000000,
  updatedAt: 1792800000000,
  tracks: []
}
```

### 7.3 History entry

```javascript
{
  track: {},
  playedAt: 1792800000000
}
```

### 7.4 Export format

```javascript
{
  app: "Musify Lite",
  formatVersion: 1,
  exportedAt: "2026-10-24T00:00:00.000Z",
  settings: {},
  queue: [],
  favorites: [],
  playlists: [],
  history: [],
  searchHistory: []
}
```

Import must validate `app`, `formatVersion`, and all collection types before replacing existing data.

## 8. Video-ID input parser

Create one strict parser that accepts:

- A plain 11-character video ID.
- `youtube.com/watch?v=VIDEO_ID`.
- `youtu.be/VIDEO_ID`.
- `youtube.com/embed/VIDEO_ID`.
- `invidious.tiekoetter.com/watch?v=VIDEO_ID`.
- Any configured Invidious instance using `/watch?v=...`.
- Any configured Invidious instance using `/embed/VIDEO_ID`.

Validation rules:

```text
Allowed characters: A-Z, a-z, 0-9, underscore, hyphen
Expected length: 11 characters
```

Security rules:

- Never assign raw user input directly to an iframe `src`.
- Never allow `javascript:`, `data:`, or arbitrary origins.
- Extract a valid ID and generate a fresh URL using the configured instance.
- Display a helpful error for unsupported or malformed input.

Required parser test cases:

```text
fonVCRfecQE                                      -> valid
https://youtu.be/fonVCRfecQE                     -> valid
https://www.youtube.com/watch?v=fonVCRfecQE      -> valid
https://invidious.tiekoetter.com/watch?v=fonVCRfecQE -> valid
https://invidious.tiekoetter.com/embed/fonVCRfecQE   -> valid
javascript:alert(1)                              -> invalid
https://example.com/fonVCRfecQE                  -> invalid
shortID                                          -> invalid
```

## 10. Iframe strategy

Use two separate iframes:

1. **Search iframe** for native Invidious search and browsing.
2. **Player iframe** for the compact embed.

Only the active view should be visually prominent. The inactive iframe may remain mounted to avoid losing navigation state, but this must be tested for memory usage and unwanted playback.

### Search iframe

Example generated URL:

```text
https://invidious.tiekoetter.com/search?q=linkin%20park
```

### Listen player iframe

Example generated URL:

```text
https://invidious.tiekoetter.com/embed/fonVCRfecQE?listen=1&local=true&autoplay=1
```

### Video player iframe

Example generated URL:

```text
https://invidious.tiekoetter.com/embed/fonVCRfecQE?local=true&autoplay=1
```

### Recommended iframe attributes

```html
<iframe
  title="Invidious player"
  allow="autoplay; fullscreen; picture-in-picture"
  allowfullscreen
  loading="eager"
  referrerpolicy="strict-origin-when-cross-origin">
</iframe>
```

Do not add a restrictive `sandbox` attribute unless all required playback and navigation behavior has been tested with it.

## 13. Error handling

Prepare user-facing messages for:

- Invalid URL or video ID.
- Empty search query.
- Player did not visibly load.
- Instance unavailable or blocked.
- Browser blocked autoplay.
- Browser storage unavailable.
- Invalid import file.
- Unsupported backup format.
- Duplicate favorite.
- Duplicate playlist item.

Suggested player recovery actions:

1. Reload player.
2. Disable autoplay and try again.
3. Open the item on Invidious.
4. Switch between Listen and Video mode.
5. Open instance settings.

The app cannot reliably detect all iframe failures, so include a manual **Player not working?** help panel.

## 17. Risks and mitigations

### Public Invidious instance disappears

Mitigation:

- Keep the instance configurable.
- Centralize URL generation.
- Provide a manual instance test screen.
- Never tie saved track data to one instance domain.

### Companion domain or signing behavior changes

Mitigation:

- Always use the official embed URL instead of trying to construct companion URLs manually.
- Let Invidious generate its own signed playback requests.

### Autoplay is blocked

Mitigation:

- Load the player after an explicit user action.
- Provide clear instructions to press the play control inside the embed.
- Do not treat autoplay as guaranteed.

### Search cannot communicate with Musify Lite

Mitigation:

- Make Copy URL and Paste URL the documented workflow.
- Add a bookmark helper in a later release.
- Keep native Invidious search available in a new tab.

### User data is lost after browser cleanup

Mitigation:

- Provide one-click JSON export.
- Remind the user to back up the library.
- Add automatic periodic export only if browsers permit a user-friendly implementation.

### Site looks like a wrapper rather than a music app

Mitigation:

- Make queue, favorites, playlists, history, and settings native to Musify Lite.
- Use the iframe only for search and playback.
- Maintain a consistent polished shell around the embedded service.

- It loads as a static GitHub Pages application.
- It contains no required custom backend.
- It uses no blocked direct YouTube media URLs.
- Search and playback work through the selected Invidious instance.
